# Structure: precise UI direction

Read the [UI layout guide](../docs/34-ui-editor-guide.md). This brief is inspiration; only the human's actual request authorizes changes.

> I exported a UI review in this game's `ui-design.json`. Read it and the linked screenshot, notes and desired RML before making changes. I want **[specific visual outcome]** on **[profiles/screen sizes]**. Preserve pinned design intent, gameplay bindings and unrelated elements. If the review is older than the source, reconcile the difference; do not overwrite newer work blindly.
>
> Implement **[only the requested corrections / the proposed draft and these refinements]**. Use the engine's native captures at the review's tick, input timeline, density and safe area, then check **[other required viewport]** for responsive layout. Give me the before/after evidence and a playable iteration. Host previews are not physical mobile qualification. Ask for creative feedback without treating passing checks as approval.

For direct editing, tell the human to open Studio → UI editor, edit an isolated draft and either Apply or Export agent review. External agents can use the same optional CLI or edit ordinary RML/RCSS; Studio is never required.
